  • A reef modelled like a magnet: healthy coral, bleached coral, bare rock and macroalgae on a lattice, nudged by heat and by neighbours. It reproduces a real bleaching event without being steered (37% bleached in the model, 40% observed).

    Reefs get stuck: once heat kills enough coral, cooling the water back does not bring it back. Mean-field models, where every patch feels every other, get stuck about 60% worse. Warming speed barely matters, and no early-warning signal fires before the slide.

    †Builds on Mumby, Hastings & Edwards (2007). Bleaching record from Scott Reef, Western Australia.

    Python · Potts model · Metropolis Monte Carlo · NumPy

    Read the write-up and code
    1. 01Calibrate, unsteered

      Free-running model against 151 days of a real bleaching event: it bleaches and recovers like the reef did.

    2. 02Give coral a way to die

      The original could never kill coral. Mortality under prolonged heat, and seaweed held back by grazers, make collapse possible.

    3. 03Warm, then cool

      Hysteresis loops at 4, 8 and 12 neighbours and mean field: the further the interaction reaches, the more stuck the reef gets.

    4. 04Speed and warnings

      Speed of warming barely matters; peak heat does. Early-warning indicators stay silent through a gradual slide.

    How the data flows
    1. Input. A daily heat-stress series and the Scott Reef coral-cover survey, each a 1D array indexed by date. The current repo version reads daily temperature and observed bleached fraction from Coral temps.xlsx (columns temp and smooth) with pandas.
    2. State. The reef is a 2D integer NumPy array (100 × 100), one cell per patch, each holding a state code: healthy, bleached, bare rock or ocean. A float array of the same shape holds each cell's accumulated heat stress.
    3. Update. Each simulated day, the Metropolis step proposes a new state for each cell, computes the energy change from its neighbours (coupling J divided by the range z) and the local heat stress, and accepts the change with probability exp(−β ΔE).
    4. Record. After each day, the count of cells in each state is appended to a dict of lists (healthy, bleached, ...), giving one time series per state.
    5. Calibrate. ABC draws many parameter sets, runs the model for each, compares its cover series with the survey, and keeps the closest sets.
    6. Output. The calibrated model is rerun across the sweeps (range z, heat ramps, a heat × coupling grid, ramp rates). Each run is reduced to a few numbers, such as hysteresis width, warning onset, tipped or survived, stored as one row per run in a table that the figures are drawn from.

  • A rebuilt agent-based model of Xylella spreading through an olive grove by spittlebug, made about 95 times faster and checked against the original. Outbreaks are all-or-nothing: 39 of 40 take the whole grove, half of it within about 2.3 years.

    A sharp threshold sits between about 16% and 29% infection per spittlebug visit. Across every felling radius and detection speed tried, felling never left more trees standing; cutting spittlebug contact did the work.

    †Recreation of Fierro, Liccardo & Porcelli (2019), Scientific Reports.

    Python · agent-based modelling · ensembles · percolation threshold

    Read the write-up and code
    1. 01Rebuild, faster

      Same rules applied to every spittlebug at once: about 95x faster, and statistically identical to the original over 12 + 200 runs.

    2. 02Find the bug that mattered

      A wrong season on day 0 gave every outbreak a head start: 38% more infection by day 600.

    3. 03Find the threshold

      A visit lasts about 18 days; outbreaks die out below roughly 16-29% infection per visit and take the grove above it.

    4. 04Test felling

      Radius x detection speed on a 1,156-tree grove: felling removes trees faster than it stops the disease.

    How the data flows
    1. Grove. A 90 × 90 NumPy array of cell types (shrub 0, tree 1, empty 2), with trees planted as 3 × 3 blocks every 5 cells. Each tree's health, infection day and symptom day are held in dicts keyed by tree position.
    2. Vectors. The spittlebugs are stored as parallel arrays with one entry per insect: x and y positions (int16), and infected and alive flags (bool). The paper's density is sampled down for speed and transmission scaled up to compensate.
    3. Time step. 48 steps per day. Each step, every insect moves to a neighbouring cell with probabilities set by the cell type and the season (tender sprouts before day 185, hard after). An insect on an infected tree may pick up the bacterium; an infected insect on a healthy tree may pass it on.
    4. Record. Each day, the S, I and R tree counts and the infected-insect fraction are appended to history lists. The transmission log adds one row per infection: source tree, target tree, day.
    5. Theory. From the log, transmissions are binned by distance to give T(d), and the front position is fitted against time to give its speed. These feed the percolation calculation and the front-speed formula, which return predicted outbreak size and a predicted timeline.
    6. Output. A three-panel figure (grove map, SIR curves with seasonal phases, insect infection rate), with the theory curves overlaid on the simulated ones.

  • A small Python library for asking how much of a correlation matrix is real: measures, estimators for messy data, factor removal, random-matrix cleaning and array stacking, behind one configurable Correlator.

    Tested against known answers (59 tests). Removing the market from 40 stocks lifts the effective number of independent bets from about 7 to 15. The engine behind the seismic and solar projects.

    †Builds on Epps (1979), Laloux, Cizeau, Bouchaud & Potters (1999), Ledoit & Wolf (2004, 2020) and Capon (1969). Prices from Yahoo Finance via yfinance.

    Python · random matrix theory · Ledoit-Wolf · pytest

    Read the write-up and code
    1. 01Measure

      Pearson, rank, Gaussian-rank, partial, distance and tail-dependence measures, all one contract.

    2. 02Remove

      Regress out a known factor or strip the top modes, with the noise band corrected for what was removed.

    3. 03Clean

      Clipping, Ledoit-Wolf and nonlinear shrinkage, tested against matrices with a known truth.

    4. 04Stack

      Minimum-variance weights are the Capon beamformer: one formula for portfolios and sensor arrays.

    How the data flows
    1. Input. A NumPy array X with one row per variable and one column per time step. For tick data, one pair of arrays per asset instead: timestamps and values, left unaligned.
    2. Measure. Each measure (Pearson, rank, tail, lead-lag, partial) is a function that returns an N × N matrix. The Hayashi–Yoshida estimator works directly on the unaligned timestamps, so nothing is resampled.
    3. Clean. From the matrix and q = N / T, compute the Marchenko–Pastur noise band. Cleaners return a new N × N matrix with the noise eigenvalues clipped or shrunk; Tyler's estimator replaces the sample matrix for heavy-tailed data.
    4. Use. Effective rank returns one number. Optimal weights return a length-N vector summing to 1. Array gain compares the noise of the weighted stack with the √N line expected from plain averaging.
    5. Output. Plain arrays and numbers, so other projects import the modules directly: the seismic denoiser uses stacking and cleaning, the Spanish solar project uses cleaning, effective rank and loadings.

  • Seismology and finance attack the same problem on 3,000 noisy recordings from the Southern California Seismic Network, scored on arrival time and first-motion direction.

    The random-matrix method's 98% pick rate was a trick of every arrival sitting in the same place; move it and the rate falls to 60%. On a synthetic array, minimum-variance weighting beats averaging - once its covariance is cleaned like a stock correlation matrix.

    †STA/LTA from Allen (1978); optimal array weights from Capon (1969). Labelled waveforms from Ross, Meier & Hauksson (2018), Southern California Seismic Network data via the SCEDC.

    Python · STA/LTA · wavelets · minimum-variance beamforming · corrlib

    Read the write-up and code
    1. 01Calibrate on quiet traces

      Picker and first-motion estimator agree with analysts on 99% and 97% of clean recordings.

    2. 02Score on noisy ones

      Five methods, with and without a random shift of the arrival.

    3. 03Stack an array

      Sensors near a road share noise; the covariance finds and cancels it.

    4. 04How much data?

      Raw optimal weights need ~0.8 s of noise to beat averaging; cleaned weights win from 0.2 s.

    Hover or tab to a box to trace everything that feeds into it and everything it feeds.

    How the data flows
    1. Input. An HDF5 file of labelled waveforms: X (one row per recording, samples along the row), Y (label), mag, snr, dist and sncls (station code). Boolean masks keep CI-network recordings that are local (≤ 50 km), small (M ≤ 3.5) and in the lowest 20% of signal-to-noise.
    2. Denoise. The selected waveforms are stacked into a matrix (recordings × samples). Its correlation matrix is eigendecomposed, only eigenvalues above the Marchenko–Pastur noise edge are kept, and the matrix is rebuilt. Each trace is then wavelet-denoised (db4, 4 levels, soft threshold).
    3. Detect. The same STA/LTA picker runs on five versions of each record: raw, imported denoiser, delay-and-sum stack, optimal weights, and optimal weights with a cleaned covariance. Each gives a pick time and a detected or missed flag.
    4. Output. One table with a row per event per method, compared with the catalogue picks to give the completeness magnitude, pick bias and crossover window.

  • Time-varying volatility from a real S&P 500 option chain, a finite-difference solver converging at order 2.09, American puts by projected SOR, SET50 against the S&P 500, and Asian options on coffee, cocoa and sugar.

    The surprise: an Asian option's delta fades as the average locks in, yet it is no easier to hedge - its risk concentrates just before averaging starts. Ignoring seasonal volatility misprices it but leaves the hedge intact.

    †Control variate from Kemna & Vorst (1990). Projected SOR as in Wilmott, Howison & Dewynne (1995). Prices from Yahoo Finance via yfinance; SET50 history from Investing.com.

    Python · Crank-Nicolson/SOR · Monte Carlo · control variates · delta hedging

    Read the write-up and code
    1. 01Read the market

      Forward, discount and forward volatility straight out of an S&P 500 chain via put-call parity.

    2. 02Check the solver

      Second-order convergence measured, American puts against a binomial tree.

    3. 03Bangkok vs New York

      SET50: more volatile, fatter-tailed, a steeper implied skew.

    4. 04Price and hedge an Asian

      Control variate cuts the noise 1,100-7,200x; a hedge simulator finds where the risk lives.

    Hover or tab to a box to trace everything that feeds into it and everything it feeds.

    How the data flows
    1. Input. One day's option chain (SPX, 4 January 2023) as a table with one row per contract: strike, expiry, call or put, bid and ask.
    2. Extract. For each expiry, calls and puts at the same strike are paired, and a put-call parity regression gives the forward price and discount factor. Implied volatilities give total variance per expiry, and differencing that gives σ(t) as a piecewise function.
    3. Solve. The price lives on a 2D NumPy grid (log-price × time), solved backwards from the payoff with SOR. For American options, each sweep also takes the maximum of the value and the payoff, which finds the exercise boundary.
    4. Check. The same contracts are priced by the exact formula, a binomial tree and Monte Carlo. The error against grid size gives the convergence order.
    5. Output. Price surfaces as arrays, the exercise boundary as one price per time step, and a convergence table.

  • Three stages: what drives the Italian power price (XGBoost and SHAP, with gas taken out first), what drives its volatility (GARCH-MIDAS), and how many months ahead a weather forecast still helps.

    Built and checked on a placeholder with planted relationships: the estimator is unbiased but imprecise, and a modest weather effect needs a long test period to detect. Real GME and ERA5 series next.

    †Builds on Guerzoni, Riso & Zoia (2026). GARCH-MIDAS from Engle, Ghysels & Sohn (2013).

    1. 01Weather to price

      Gas-relative target; SHAP recovers the heating and cooling U-shape.

    2. 02Weather to volatility

      GARCH-MIDAS recovers the planted weather effect on average over ten simulated decades.

    3. 03Forecast to volatility

      With a strong effect, forecasts help out to about 1-2 months.

    How the data flows

    The plan for real data; the code currently runs on a placeholder of the same shape.

    1. Input. GME daily day-ahead prices, ERA5 daily weather over Italy, and SEAS5 25-member monthly forecasts, aligned into one table indexed by date.
    2. Features. Daily log returns of price. Monthly weather-extreme indices (one value per month), computed the same way from ERA5 and from each SEAS5 member after quantile-mapping bias correction.
    3. Fit. Three models on the same training window: GARCH(1,1) on returns alone, GARCH-MIDAS with ERA5 extremes, and GARCH-MIDAS with forecast extremes. Each outputs a daily variance forecast.
    4. Score. On the test window, each forecast is compared with realised variance using QLIKE and MSE, and a Diebold–Mariano test checks whether the differences are significant.
    5. Output. A table of losses per model per forecast lead. The skill horizon is the lead at which the forecast model stops beating the no-weather model.

  • How far does a cloud reach? An Anemoi ML-ready ERA5 dataset for Iberia, built with tested data-quality checks, CI and Docker, feeds a seasonal analysis of how correlated 25 Spanish solar sites are - the diversification a solar fleet really has.

    On ERA5 2023 the weather stays correlated over 350-670 km, so 25 sites behave like 3-4. A shared daily artefact, invisible on synthetic data, had to be removed first. Next: CERRA at 5.5 km, prices and cannibalisation, and AI (AIFS) versus physics forecasts scored in money.

    How the data flows

    The full plan; the first stage, how correlated the sites are, is done.

    1. Input. Hourly ERA5 radiation and temperature at 20–40 site locations (a table of hours × sites), and hourly ENTSO-E day-ahead prices for Spain.
    2. Generation. A simple panel model turns each site's weather into hourly output. The clear-sky profile is subtracted, leaving only weather-driven deviations, in the same hours × sites shape.
    3. Correlation. Site × site correlation of the deviations, by season. Fitting ρ(d) = exp(−d / L) against distance gives the decay length L; the matrix is cleaned with corrlib.
    4. Structure. Effective rank of the cleaned matrix, each site's loading on the shared mode, and each site's capture rate: its output-weighted average price divided by the plain average price.
    5. Output. Five allocation arms, each a vector of capacity shares, back-tested over the years into one table of revenue and worst-year results.
